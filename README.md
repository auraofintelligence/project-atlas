# Project Atlas

**Find the idea. Follow the pattern.**

Project Atlas is the public navigation and provenance layer for Luke Nathan Hayes's connected body of Aura of Intelligence work. It is a plain-language, magazine-style doorway for exploring projects, their development history and the recurring architecture beneath them, without needing to understand GitHub.

It is a map of the work that has been surfaced so far, not the complete archive of a life or an assertion that every project is active, finished or formally adopted. Joyful Responsible Abundance is the organising principle; individual implementations can evolve, coexist or be retired.

This is an initial editorial classification, not a completed substantive audit, an owner-confirmed list of deprecated projects or a measure of project readiness. For downstream project matching and opportunity research, begin with the current/supporting subset, then check the project's own README, scope, release state, geographic applicability, dependencies and exclusions. Historical material can provide evidence without becoming a current recommendation. No automatic opportunity-matching engine is implemented by this Atlas.

### Search and navigation

- Search by project text and filter by lifecycle, original-build year, family, public-page availability, standalone website status and related-work availability.
- Sort by repository creation date (newest or oldest), newly completed or meaningfully rebuilt work, public pages, most/least connected and A to Z.
- Follow evidence-backed relationships and documented implementation storylines. Related-work panels expose all listed public neighbours, rather than a small sample.
- Prefer the project's actual public deployment when known; provide its public GitHub source separately where it exists. Standalone initiatives do not acquire invented repositories or dates.
- Print a handout-ready directory of the public catalogue with readable addresses and locally generated SVG QR codes. No external QR generation service is required.
- Start on the home page with 14 curated repository-backed major projects, led by Open Record, Aura Genesis Protocol and 82 Claytons, alongside Gamify Democracy and Ready SET Co-op.

### Dates, releases and evidence

The original substantive build date is the earliest audited evidence of meaningful project material, expressed as a Brisbane local date. It is not GitHub's latest-updated date. Licence changes, spelling fixes and housekeeping do not make older work newly built.

GitHub repository creation timestamps are recorded independently and determine the default catalogue sort. Current-release notes identify meaningful rebuilds, such as Global Group Marriages v2, without erasing the earlier history. Missing original build evidence stays unknown.

### The recurring braid

[The recurring braid](https://auraofintelligence.github.io/project-atlas/pattern-braid.html) identifies ten structural patterns:

1. Reflection → geometry → memory → action
2. Individual → conversation → community → civilisation
3. Human meaning → machine-readable structure
4. Human cognition ↔ agent cognition
5. World sensed → world experienced → self observed
6. Local sovereignty → federation
7. Question → model → simulate → choose → measure
8. Time → contribution → reciprocity
9. Interface → wearable → environment
10. Provenance → imagination → correction

Underneath these sits a general-purpose legibility pattern:

**Opaque system → source trail → addressable model → human interpretation → simulation → choice → feedback → revised model.**

It connects work in law, personal reflection, spatial digital twins, agent orchestration and civic/civilisational systems. The purpose is to make complex systems inspectable, navigable and correctable by people and machines without erasing human judgement or source evidence.

## Provenance and the living archive

The [provenance room](https://auraofintelligence.github.io/project-atlas/pattern-provenance.html) distinguishes four evidence layers:

| Layer | Examples |
| --- | --- |
| Authored | Documents, diagrams, wireframes, songs, submissions, websites and repositories |
| Lived | Travel, photographs, video, events, places and experiences |
| Computational | Commits, prompts, model outputs, agent traces, datasets and structured models |
| Public | Published work, performances, submissions, organisations, talks and community projects |

A proposed Personal Provenance Vault keeps raw private material under its owner's control while permitting deliberately selected evidence records: pointers or hashes, dates, chosen location precision, evidence class, description, related patterns and permission state.

The public Atlas currently sees predominantly authored work. It does not publish the full private life archive, personal movement history, private conversations or raw media, and it does not implement the complete proposed vault.

Memory → evidence → interpretation → pattern → project → consequence complements the question/model/simulation loop. Earlier ideas are evidence of development, not automatic current policy.

## GAJRA Earth: continuity and correction

[GAJRA pattern ancestry](https://auraofintelligence.github.io/project-atlas/pattern-gajra.html) traces Joyful Responsible Abundance, values mapping and human/AI co-development through the earlier 2022-2023 work into the current direction.

Persistent principles include reflection before alignment, cultural plurality, local participation, art/music/games as coordination media, personal Aura of Intelligence and the expansion of human agency.

Earlier ICO, token, DAO, staking, NFT and single-world-vote mechanisms are retained as historical experiments. They are not presented as current financing commitments or adopted governance.

The later direction emphasises locally rooted associations, federation rather than central control, consent, provenance, withdrawal, plurality and C-Hour recognition of verified freely given human time without monetary conversion.

## Update the data

The browser reads `data/projects.json` for repository-backed work and `data/external-projects.json` for standalone websites, including Gamify Democracy and Ready SET Co-op. External records have their own editorial identity, verified source links where available and no invented repository or creation date. Their local QR files are generated independently in `assets/external-qr/`. The daily [public Atlas reconciliation workflow](.github/workflows/public-atlas-reconciliation.yml) is configured for 05:20 Brisbane time (19:20 UTC on the previous day) and audits public inventory without publishing unreviewed projects. Reviewed additions are applied only by the defined reviewed-file/workflow push trigger or an explicitly enabled manual dispatch. Review new candidates in `data/reviewed-public-additions-2026-11-24.json`; the apply step verifies visibility, creation metadata, public links, icons and QR codes, then validates before committing. Original substantive build dates are left unknown where evidence is absent. Private or sensitive work is excluded.

```powershell
  --manual data\manual-projects.json `
  --output data\projects.json
```

`data/manual-projects.json` holds editorial additions and overrides once their public destination, original build date and relationship evidence are confirmed. `freshlyCompleted` remains available for the recent-work sort. Its `excludedProjectNames` list keeps deleted and archived repositories out of cards, search, QR codes and related-project links, while leaving the source audit intact. A dated public refresh file is useful when several new pages launch together.

`data/lifecycle.json` holds lifecycle classifications and their explanatory notes. Keep it aligned with catalogue changes; records without a classification default to review pending in the browser. `data/project-icons.json` tracks repository icon assets, sources and approved fallbacks. `featuredProjectNames` sets the major-project order on the home page. The build regenerates those home links from this list. The Projects page has a single directory, ordered by repository creation date, newest first by default. `data/repository-creation-dates.json` records GitHub's `created_at` timestamps, independently of substantive build history and later updates; refresh this file when adding repositories. Card creation dates use Brisbane local time. Open Record links directly to its public GitHub record; it does not have a separate GitHub Pages site. 7-Mile uses its published planning-workbench address.

The generator rejects non-public repository links and invalid build dates. It does not copy local paths, unpublished source material or private notes into the public dataset.

## Maintenance and validation

| Workflow | Purpose |
| --- | --- |
| [Public Atlas reconciliation](.github/workflows/public-atlas-reconciliation.yml) | Scheduled read-only audit; separately gated apply of reviewed public projects |
| [Standalone websites and deployment links](.github/workflows/external-projects.yml) | Repair canonical deployment links and editorial records, rebuild QR assets and validate standalone identities |
| [Repair reviewed project icons](.github/workflows/repair-reviewed-icons.yml) | Retrieve original artwork for the eleven reviewed additions and validate before committing |
| [Zero em dash punctuation](.github/workflows/zero-em-dash.yml) | Check or repair tracked text and validate the catalogue on matching pushes, manual runs and daily schedule (05:35 Brisbane) |

The workflows preserve private/sensitive exclusions and use shared concurrency controls for catalogue writes. The reviewed-additions manifest is not a general instruction to publish every newly discovered repository. Verify the target repository is public, the destination is appropriate, the icon is authentic and the dates are supported before approving a record.

## Check it

```powershell
python scripts/validate_atlas.py
node scripts/validate_external_projects.mjs
node --check app.js
python scripts/no_em_dashes.py
```

The standalone validator checks the official Gamify Democracy mark, Ready SET Co-op name and sourced tide emblem, known related repositories and public QR targets. The primary validator checks the repository-backed catalogue, source links, original-date evidence, relationship integrity, local QR files and icon manifest. The punctuation check also detects encoded forms of the unwanted character.

For a local preview:

```powershell
python -m http.server 8000
```

Then open `http://localhost:8000`. The site is static and is already published through GitHub Pages. JavaScript loads the public catalogue and metadata; no application backend or account system is required for browsing.

## Regenerate the QR codes

The printable directory uses local SVG QR codes. Each code targets the project's public page when one exists, otherwise its public GitHub repository. They are generated locally, so no visitor address or project URL is sent to a QR-code service.

```powershell
npm ci
npm run build:qr
```

Run the normal check afterwards. It confirms that every included project has a matching QR SVG with the intended public target.

## Repository structure and limits

- `app.js`, `styles.css`, `pattern-ancestry.css` and the nine HTML pages provide the static experience.
- `data/projects.json` is the generated repository-backed catalogue; `data/external-projects.json` adds standalone sites in the browser.
- `data/manual-projects.json`, audit/delta files and creation-date records preserve rebuild inputs and editorial decisions.
- `data/lifecycle.json` separates current and supporting work from historical and unreviewed material.
- `data/project-icons.json`, `assets/project-icons/`, `assets/external-icons/`, `assets/qr/` and `assets/external-qr/` hold artwork provenance and QR assets.
- `scripts/` contains the data builder, reconciliation, deployment-link repair, QR generator and validation tools. Full historical rebuilds require the neighbouring Field Library audit inputs identified above.
- `robots.txt` and `sitemap.xml` support search discovery. The sitemap currently lists only the Atlas homepage; expanding it to include the purpose-specific rooms is a potential maintenance task.

The catalogue is deliberately selective and cannot substitute for reading the linked project. Relationships, historical eras and lifecycle decisions are evidence-backed where available but remain open to correction. A place to join in is an invitation to explore, not a guaranteed job, approved partnership or automated enrolment.
